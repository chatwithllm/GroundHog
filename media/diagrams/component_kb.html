MOBO

Motherboard — SP5 Board

Salvaged pool-cleaner board · power + motors + charging
Working
board photo
media/diagrams/sp5_board.jpg

Role

Kept whole as the 24V source, battery charge path, motor mounts, and Hall-encoder source. Its own MCU is dead/bypassed — the internal H-bridges are gated and can't be opened in firmware, so we drive the motors externally.

Specs

MCUGD32F103CB clone — RDP read-locked, bypassed
Pack6S 24V Li-ion, on-board BMS + charger
Motors3× integrated-driver BLDC (L / R / blade)
Chargingpassive, MCU-independent (works w/ MCU dead)

Connections

  • pack terminals — 24V tap → drivers / BEC
  • motor headers — 5-wire BLDC each (VCC·GND·PWM·DIR·FG)
  • encoder Vcc — ~5V rail (measure before tapping)

Reflash / recover

not reprogrammable
MCU is RDP read-locked and bypassed by design. Nothing to flash — the board is passive infrastructure.

Replace / gotchas

  • One-off salvage part — no drop-in replacement. Preserve it.
  • Do not gut the board — charging rides on it (dies if removed).
  • CON1 debug console is flaky on the stock board; clean on ours.
  • 24V is live — fuse taps, double-check polarity (no reverse protection downstream).

ESP

Motor Interface — ESP32

Per-wheel actuator · C6 now → Lonely Binary S3
Working
C6 / S3 pinout
media/diagrams/esp_c6_pinout.png

Role

Turns the F405's per-wheel commands into what the integrated BLDC drivers need: inverted PWM (0% duty = full speed), a DIR line via level-shifter, FG tacho read-back, and a deadman that kills the motors on signal loss. Also hosts BLE + WiFi manual control.

Specs

NowXIAO ESP32-C6 · BLE-only · 2.4GHz WiFi
HostESPHome (esp-idf) · bldc-c6.local
NextLonely Binary S3 (WROOM-1 N16R8) · ≤8 motors · CAN
Logic3.3V — NOT 5V-tolerant

Connections (C6)

  • PWM direct — D0 D3 D8 (GPIO0/21/19)
  • DIR + FG via BSS138 — GPIO1/2/22/23/20/18
  • RC-PWM in from F405 — D6 D7 (GPIO16/17)

Reflash

esphome · OTA or USB
# over WiFi (OTA)
$ esphome run firmware/esphome/bldc-c6.yaml
# USB fallback (C6 = /dev/ttyACM0 on the Pi)
$ esptool.py --chip esp32c6 -p /dev/ttyACM0 \
      write_flash 0x0 bldc-c6.factory.bin

Replace / gotchas

  • Needs local secrets.yaml (WiFi + API key) — copy from .example.
  • 5V killed 3 boards: FG/DIR must go through the BSS138 shifter, never straight to a GPIO.
  • Avoid strapping pins (C6: 4/5/8/9/15).
  • After swap, re-add to Home Assistant with the API encryption key.

FC

Flight Controller — Radiolink F405

The brain · ArduPilot Rover 4.7
Working
F405 pinout
media/diagrams/f405_pinout.png

Role

Reads the FlySky RC, does the skid-steer mix, arming, and RC failsafe, and emits two per-wheel throttle channels to the ESP. Later: RTK-driven GUIDED/AUTO waypoint navigation.

Specs

TargetArduPilot RadiolinkF405 · Rover 4.7
MCUSTM32F405 · 5 UART · 7 PWM · 3.3V
Compassnone — needs external / dual-GPS heading
PowerVIN battery (5V pads dead on USB-only)

Connections

  • FlySky iA6B i-BUS → R4 / PA1 (SERIAL4 = RCIN)
  • S1 ThrottleLeft(73) · S3 ThrottleRight(74) → ESP D6/D7
  • USB → Pi (MAVLink + power + flashing)

Reflash + key params

Mission Planner / USB
# Install Firmware → ArduRover (RadiolinkF405), then load params:
SERIAL4_PROTOCOL 23   # RCIN on R4
SERIAL2_PROTOCOL -1   # stop SBUS pad hijacking RCIN
SERVO1_FUNCTION  73   SERVO3_FUNCTION 74
RCMAP_YAW 1  RCMAP_PITCH 3   # no channel collisions!
PILOT_STEER_TYPE 2   MOT_STR_THR_MIX 0.7
MOT_SLEWRATE 0   RC5_OPTION 153  # arm switch

Replace / gotchas

  • No two RCMAP_* on the same channel — collisions weaken/kill steering.
  • SBUS pad (SERIAL2) is inverted and steals RCIN — disable it.
  • Accel-cal stuck? reboot, then PREFLIGHT_CALIBRATION param5=4.
  • 5V pads are dead on USB alone — power from VIN to run the RX.

PI

Companion — Raspberry Pi + LC29H

RTK corrections · MAVLink · autonomy host
Working
Pi + LC29H HAT photo
media/diagrams/pi_lc29h.jpg

Role

Runs the NTRIP → RTCM pipeline into the LC29H for centimeter fix, bridges MAVLink to the F405, and hosts higher-level autonomy (boundary record, coverage planning) + camera. Powers the C6 and F405.

Specs

Accessssh npalakurla@rtk
GPSLC29H RTK HAT · /dev/serial0 @ 115200
Correctionsstr2str ← INCORS VRS MSM4_iMAX
Fix log/var/log/rtk/live-nmea.log

Connections

  • LC29H HAT — Pi 40-pin header (UART + power)
  • antenna — u.FL → SMA (active, needs clear sky)
  • USB → F405 (MAVLink) · 5V → C6

Reflash / recover

reimage SD + redeploy pipeline
# flash Raspberry Pi OS Lite, then restore:
#   /usr/local/bin/rtk-{port-relay.py,ntrip.sh}
#   /etc/rtk-ntrip.env  (chmod 600, creds)
$ sudo systemctl enable --now rtk-port-relay rtk-ntrip
$ systemctl is-active rtk-port-relay rtk-ntrip

Replace / gotchas

  • Never open /dev/serial0 directly — it knocks the LC29H out of RTK. Read live-nmea.log instead.
  • RTK needs open sky — indoors you only get q=1 (standalone).
  • A warm reboot does not power-cycle the HAT (rides always-on rails).
  • Don't spam receiver resets — each zeroes RTK convergence.

RC

RC Link — FlySky FS-i6

Manual control · TX FS-i6 + RX iA6B
Working
TX + RX photo
media/diagrams/flysky.jpg

Role

Direct manual RC — the hands-on drive + arm/mode path. Feeds the F405 over i-BUS; the F405 does the mixing.

Specs

TXFlySky FS-i6 · 6+ ch
RXiA6B · i-BUS (non-inverted)
Armswitch on CH5 (RC5_OPTION 153)

Connections

  • iA6B i-BUS (S) → F405 R4 (SERIAL4)
  • V+ / G → 5V / GND (from F405 VIN rail)

Reflash / config

TX menu — no firmware flash
Configured on the TX itself: bind RX, set channels + failsafe (throttle-cut on loss), dual-rate per switch. No firmware to flash.

Replace / gotchas

  • Bad dual-rate / throttle-curve silently clamps throttle — verify curves flat/full.
  • Sticks freeze while a menu is open — read channels from the main screen.
  • Mixes gone wrong → factory-reset the TX and rebuild.
  • On RX swap: rebind + reset channel map and failsafe.

CAM

Depth Camera — RealSense D455

Stereo depth + RGB + IMU · perception (live)
Working
D455 photo
media/diagrams/d455.jpg

Role

Gives the robot 3D perception: obstacle avoidance, visual-inertial odometry (a heading source the F405 lacks + an RTK-dropout backstop), and yard mapping. The RGB stream doubles as FPV + a safety camera (stop the blade if a person enters frame).

Specs

RGBup to 1280×800 @ 30 (YUYV)
Depthstereo 1280×720 @ 90 · 0.4–6 m in / ~20 m out
IRglobal-shutter stereo (low light)
IMU6-axis accel + gyro (BMI055)
BusUSB 3.2 · ~2–3.5 W

Connections

  • USB3 → Pi (5 Gbps — needs a blue SS port)
  • nodes — video0 depth · video2 IR · video4 RGB

Setup (SDK on host, not firmware)

build librealsense from source
# no apt pkg (Debian trixie) + no py3.13/aarch64 wheel → source build
$ cmake .. -DFORCE_RSUSB_BACKEND=true \
      -DBUILD_PYTHON_BINDINGS=true
$ make -j3 && sudo make install && sudo ldconfig
$ rs-enumerate-devices        # verify streams + IMU

Replace / gotchas

  • Needs a USB3 (blue/SS) port for depth+RGB — USB2 = RGB only.
  • No apt package on trixie + no pip wheel (py3.13/aarch64) → build from source.
  • Pi 4B can't run full SLAM/VIO at high res — downscale or offload heavy mapping.
  • Use FORCE_RSUSB_BACKEND=true on the Pi (userspace libusb, no kernel patch).
  • ~2–3.5 W draw — mind the shared Pi supply with F405 + C6.
